## 环境总览

| 依赖 | 版本要求 | 用途 | 三端 |
| --- | --- | --- | --- |
| Node.js | ≥ 20（建议 20 LTS 或 22 LTS；本机开发用 v26） | 前端构建、Tauri CLI | 全部 |
| pnpm | ≥ 9（本机 11.7；CI 用 11） | 包管理（仓库含 `pnpm-lock.yaml`） | 全部 |
| Rust | stable（rustup；`rust-version = 1.77.2`） | Tauri 后端 | 全部 |
| Xcode Command Line Tools / Xcode | 最新稳定版 | macOS 链接、打包 | macOS |
| Visual Studio Build Tools（C++ 桌面开发） | 2019/2022 | MSVC 链接器 | Windows |
| WebView2 Runtime | Evergreen | 运行时（Win10 1803+ 自带） | Windows |
| JDK | **17**（Temurin 17） | Android Gradle 构建 | Android |
| Android SDK | `platforms;android-35`、`build-tools;35.0.0`、`platform-tools` | Android 构建 | Android |
| Android NDK | **27.0.12077973**（r27） | Rust 交叉编译 | Android |

> 本项目把 Rust 工具链放在仓库内 `.toolchain/`（`RUSTUP_HOME` / `CARGO_HOME` / `PATH` 由 `scripts/env.sh` 导出），这是**可选项**：你也可以直接使用自己的 rustup 全局工具链。

## 首次构建前置

1. **安装前端依赖**（三端通用，在项目根目录执行）：

   ```bash
   pnpm install
   ```

2. **准备图标**：`src-tauri/tauri.conf.json` 的 `bundle.icon` 引用了 `src-tauri/icons/` 下的图标文件。如果该目录为空（干净检出 / 图标未提交），先准备一张 ≥1024×1024 的 PNG 或用已有 `assets/` 素材生成：

   ```bash
   pnpm tauri icon assets/app-icon.png   # 生成 src-tauri/icons/ 下的全套图标
   ```

   缺少图标时打包阶段会报错（开发模式 `pnpm tauri dev` 通常不受影响）。

3. **（可选）使用项目内 Rust 工具链**：

   ```bash
   source scripts/env.sh
   rustc -V && cargo -V   # 应输出 1.9x stable
   ```

   之后所有 `pnpm tauri ...` 命令都在同一 shell 内执行即可；不开新终端前环境变量一直有效。

## macOS

### 开发

```bash
pnpm install
source scripts/env.sh      # 可选：使用项目内 Rust 工具链
pnpm tauri dev             # 等价于 pnpm dev:app；会先启动 Vite
```

只调 UI、不碰 Rust / 真实云盘时：

```bash
pnpm dev:mock              # 浏览器打开 http://localhost:1420（mock 数据）
```

### 构建

```bash
pnpm install
source scripts/env.sh      # 可选
pnpm tauri build
```

产物（Apple Silicon，默认）：

```text
src-tauri/target/release/bundle/dmg/互联_0.1.0_aarch64.dmg
src-tauri/target/release/bundle/macos/互联.app
```

> Intel Mac 产物名通常为 `互联_0.1.0_x64.dmg`。也可显式指定：`pnpm tauri build --bundles app,dmg`。

### 未签名 App 的 Gatekeeper 处理

未签名 / 未公证的 App 首次打开会被 macOS 拦截（"无法验证开发者"）。处理方式：

1. 在「应用程序」中 **右键 → 打开 → 打开**；或
2. 命令行移除隔离属性：

   ```bash
   xattr -cr "/Applications/互联.app"
   ```

### 可选：签名与公证

正式分发需要 Apple Developer 账号。Tauri 2 支持通过环境变量完成签名/公证（在 CI 中从 secrets 注入，见 [CI 一节](#cigithub-actions)）；本地可参考：

```bash
# 示例：仅说明涉及的环境变量名，具体值请使用你自己的证书/账号
export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)"
export APPLE_CERTIFICATE_PASSWORD="..."
export APPLE_ID="you@example.com"
export APPLE_PASSWORD="app-specific-password"
export APPLE_TEAM_ID="TEAMID"
pnpm tauri build
```

> 未配置签名时构建仍可成功，产物为未签名版本（适合自用/内测）。

## Windows

### 依赖

- Windows 10 1803+ / Windows 11 x64；
- Node.js ≥ 20、pnpm；
- **Rust MSVC 工具链**：`rustup default stable-x86_64-pc-windows-msvc`；
- **Visual Studio Build Tools 2019/2022**，勾选「使用 C++ 的桌面开发」（提供 `link.exe`/Windows SDK）；
- **WebView2 运行时**：Win10 1803+ 通常自带；开发机可装 Evergreen 运行时，安装包也可附带 WebView2 Bootstrapper（见 Tauri 文档）。

### 构建

在 PowerShell（建议 **x64 Native Tools Command Prompt for VS**，或普通 PowerShell + 已安装 Build Tools）中：

```powershell
cd 项目目录\互联
pnpm install
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1
```

或手动执行：

```powershell
pnpm tauri build --bundles nsis
```

> **为什么要带 `--bundles nsis`**：`tauri.conf.json` 的 `bundle.targets` 是面向 macOS 的 `["app", "dmg"]`，在 Windows 上不适用；显式指定 `nsis` 才能稳定产出安装包（构建脚本与 CI 已内置该参数）。
> 如需 MSI，可用 `pnpm tauri build --bundles msi`（需要 WiX 工具链，Tauri 会按需准备）。

产物：

```text
src-tauri\target\release\bundle\nsis\互联_0.1.0_x64-setup.exe
```

### 关于在 macOS 上交叉编译 Windows

不推荐、也不保证可行：需要 MSVC 链接器、Windows SDK、WebView2 等一整套工具链。请使用 **Windows 机器或 CI 的 `windows-latest`** 构建 Windows 产物。

### 可选：代码签名

未签名安装包会触发 SmartScreen「未知发布者」提示。正式分发需代码签名证书：

- 在 `src-tauri/tauri.conf.json` 的 `bundle.windows` 中配置证书指纹/时间戳服务器，或使用 `signCommand` 自定义签名（例如 Azure Trusted Signing、硬件 USB 证书）；
- 证书与密码不要进仓库，放 CI secrets / 本机安全存储。

## Android

> 本机 macOS 未完成 Android 环境安装，以下命令按 Tauri 2 官方流程编写，**尚未在本机跑到产物**（脚本已做静态检查）。首次使用请预留 30–60 分钟下载 SDK/NDK/Gradle 依赖。

### 1）依赖安装

- **JDK 17**（Temurin 17 推荐），设置 `JAVA_HOME`：

  ```bash
  export JAVA_HOME="$(/usr/libexec/java_home -v 17)"   # macOS
  java -version                                        # 应显示 17.x
  ```

- **Android SDK + 命令行工具**（Android Studio 的 SDK Manager 或独立 `sdkmanager` 均可）：

  ```bash
  export ANDROID_HOME="$HOME/Library/Android/sdk"      # 按你的实际安装路径修改
  export ANDROID_SDK_ROOT="$ANDROID_HOME"
  export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"

  sdkmanager --licenses
  sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0" "ndk;27.0.12077973"
  ```

- **Rust Android 目标**（脚本会自动补装，手动可执行）：

  ```bash
  rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android i686-linux-android
  ```

- **NDK 环境变量**（Tauri/Gradle 需要能找到 NDK）：

  ```bash
  export NDK_HOME="$ANDROID_HOME/ndk/27.0.12077973"
  export ANDROID_NDK_HOME="$NDK_HOME"
  ```

### 2）初始化 Android 工程（只需一次，幂等）

```bash
NONINTERACTIVE=1 pnpm tauri android init --ci
```

- 生成 `src-tauri/gen/android/`（Gradle 工程），**该目录不需要提交**（构建脚本会检测是否存在再决定是否初始化）；
- `--ci` 用于跳过交互提问（`tauri android init --help` 中可见该参数；`CI=1` 环境变量等价），CI 中必须使用；
- 初始化会在 `src-tauri/gen/android/` 里创建 debug 签名配置，默认使用本机 `~/.android/debug.keystore`（缺失时脚本用 `keytool` 生成）。

### 3）构建

```bash
# 调试 APK（debug 签名，可直接安装）
pnpm tauri android build --debug --apk

# 发布 AAB（应用商店用；需要自行配置 release 签名）
pnpm tauri android build --aab

# 发布 APK（同样需要 release 签名）
pnpm tauri android build --apk
```

产物（路径以构建输出与脚本 `find` 结果为准，常见为）：

```text
src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
# 或按 ABI 拆分时：
src-tauri/gen/android/app/build/outputs/apk/arm64/debug/app-arm64-debug.apk
```

安装到手机（可选）：

```bash
adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

### 4）签名说明

- **debug 包**：使用 Gradle 自动生成的 `~/.android/debug.keystore`，可直接安装，不适合分发；
- **release 包**：需要自己的 keystore。把 keystore 放到仓库外，按 Tauri 生成工程中的签名配置注入密码（或使用 `tauri android init` 时的交互配置），**不要把 keystore/密码提交到仓库**；
- 脚本默认只构建 **debug APK**；需要 release 时手动执行上面的 `--aab` / `--apk` 并配置签名。

## 构建脚本一览

| 脚本 | 平台 | 作用 |
| --- | --- | --- |
| `scripts/build-macos.sh` | macOS | 检查 node/pnpm/Rust/Xcode → 必要时 `pnpm install` → `pnpm tauri build` → 打印 dmg/app 路径 |
| `scripts/build-windows.ps1` | Windows | 检查 node/pnpm/Rust/MSVC → 必要时安装依赖 → `pnpm tauri build --bundles nsis` → 打印 exe 路径 |
| `scripts/build-android.sh` | macOS / Linux | 检查 node/pnpm/Rust/JDK17/SDK/NDK → 补装 Rust Android targets → 幂等 `android init` → debug APK → 打印 APK 路径 |

使用示例：

```bash
bash scripts/build-macos.sh
bash scripts/build-android.sh
```

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1
```

脚本都是「失败即停」并给出修复提示，适合本地与 CI 复用。

## 诊断与命令行入口

桌面端 App 内置以下命令行参数，用于首次配置、排障与发布前冒烟（后两个为内部验证用）：

| 参数 | 作用 | 示例 |
| --- | --- | --- |
| `--import-cli` | 读取本机 `~/.aliyun/pds_config.json`，自动识别账号与默认空间，写入 App 配置后退出 | `"/Applications/互联.app/Contents/MacOS/互联" --import-cli` |
| `--selftest` | 真实上传一个小文件再下载回来做字节比对；成功输出 `SELFTEST_UPLOAD_DOWNLOAD OK` 后退出 | `"/Applications/互联.app/Contents/MacOS/互联" --selftest` |
| `--hidden` | 启动时只驻留托盘、不显示窗口（开机自启使用，配合「关闭窗口时驻留托盘」） | `互联 --hidden` |
| `--close-after <秒>` | 内部验证用：N 秒后模拟点击关闭窗口，走 `CloseRequested` → 销毁窗口 → 驻留托盘的完整路径 | `互联 --close-after 5` |
| `--destroy-after <秒>` | 内部验证用：N 秒后直接销毁主窗口（不经过关闭事件），用于对比验证资源释放 | `互联 --destroy-after 5` |

说明：

- macOS 可执行文件位于 `互联.app/Contents/MacOS/互联`；Windows 为安装目录下的 `互联.exe`。
- 这些参数会真实访问云盘（`--selftest` 会上传/下载并清理临时文件），请在有网络、已配置凭据时使用；输出在终端里可见（双击启动看不到）。
- 排障时优先跑 `--selftest`：能区分「凭据/网络问题」和「App 内部问题」。
- Rust 侧还有 `#[ignore]` 的真机联调用例（见 [验证状态与未验证项](#验证状态与未验证项)），CI 默认不会运行。

## CI（GitHub Actions）

文件：`.github/workflows/build.yml`。

### 触发方式

- 手动触发：仓库 Actions 页面 → 选择 workflow → **Run workflow**；
- 打 tag 推送（如 `v0.1.0`）自动构建三端；
- 推送到 `main` 分支也会构建（可自行删除该触发以节省额度）。

### 三个独立 job

| Job | Runner | 产物 | 关键步骤 |
| --- | --- | --- | --- |
| `macos` | `macos-14`（Apple Silicon） | `linkup-macos-arm64`（dmg + 压缩的 .app） | `pnpm tauri build` |
| `windows` | `windows-latest`（x64） | `linkup-windows-x64`（NSIS setup.exe） | `pnpm tauri build --bundles nsis` |
| `android` | `ubuntu-latest`（x64） | `linkup-android-debug-apk`（debug APK） | JDK 17 + SDK/NDK + `android init` + `android build --debug --apk` |

- 三个 job **互不依赖**，任一失败不影响其他平台产物；
- actions 版本：`actions/checkout@v4`、`pnpm/action-setup@v4`、`actions/setup-node@v4`、`dtolnay/rust-toolchain@stable`、`swatinem/rust-cache@v2`、`actions/upload-artifact@v4`，Android 额外用 `actions/setup-java@v4`（temurin 17）。
> Android **不再使用** `android-actions/setup-android@v3`：该 action 会去安装早已下线的 `tools` 包，在 runner 自带的 cmdline-tools 16 上直接失败（实测 2026-10-21：`Warning: Failed to find package 'tools'` → exit 1）。workflow 改为复用 ubuntu runner 预装的 Android SDK（`/usr/local/lib/android/sdk`）并用 `sdkmanager` 安装所需组件。
- CI 环境：Node.js 22 + pnpm 11（`pnpm install --frozen-lockfile`），Rust stable；三个 job 并行，互不依赖；
- 产物在页面底部 Artifacts 下载，保留 14 天；
- **CI 只做构建，不跑真实云盘用例**：`pds.rs` / `transfer.rs` 中的 `live_*` 测试带 `#[ignore]`（需要本机 `~/.aliyun/pds_config.json` 凭据），默认 `cargo test` 与 workflow 都不会执行，避免 CI 依赖真实账号。

### 签名 / 公证（可选，默认不做）

未配置 secrets 时 workflow 产出**未签名**产物（可自用/内测）。需要正式分发时：

- **macOS 签名 + 公证**：在 `macos` job 增加 `APPLE_CERTIFICATE`、`APPLE_CERTIFICATE_PASSWORD`、`APPLE_SIGNING_IDENTITY`、`APPLE_ID`、`APPLE_PASSWORD`、`APPLE_TEAM_ID` 等 secrets（workflow 内已留注释位置）；
- **Windows 代码签名**：证书经 secrets 注入并在 `bundle.windows` 配置签名（不要在仓库提交证书）；
- **Android release 签名**：CI 默认只构建 debug APK；发布版需配置 keystore secrets 并改为 `android build --aab`。

> GitHub 对公开仓库的 macOS runner 与总时长有额度限制；私有仓库请留意 Actions 计费。

## 常见构建问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `cargo: command not found` / `rustc: not installed` | 未装 Rust 或未加载项目工具链 | `source scripts/env.sh`，或安装 rustup 后重开终端 |
| 打包报错找不到图标 | `src-tauri/icons/` 为空 | `pnpm tauri icon assets/app-icon.png` 或用 `tauri icon` 生成全套 |
| `pnpm install` 报 lockfile 不一致 | 依赖变更后 lockfile 未更新 | 本地执行 `pnpm install` 更新并提交 `pnpm-lock.yaml`；CI 用 `--frozen-lockfile` 校验 |
| Windows 链接器报错 / `link.exe not found` | 未装 VS Build Tools C++ 或不在 VS 环境下 | 安装「使用 C++ 的桌面开发」；在 Native Tools 命令行中重试 |
| Windows 启动白屏 | 缺 WebView2 运行时 | 安装 Evergreen WebView2 Runtime |
| macOS 提示"无法验证开发者" | 未签名/未公证 | 右键打开，或 `xattr -cr "/Applications/互联.app"` |
| Android 报 `JAVA_HOME` 错误 / 版本不对 | 不是 JDK 17 | 安装 Temurin 17 并设置 `JAVA_HOME` |
| Android 报找不到 SDK / NDK | `ANDROID_HOME` / `NDK_HOME` 未设置 | 按 [Android 一节](#android) 导出环境变量 |
| `tauri android init` 卡在交互提问 | CI/自动化环境没有 TTY | 加 `--ci` 与 `NONINTERACTIVE=1` |
| `sdkmanager` 报 license 未接受 | 未执行 `sdkmanager --licenses` | 执行并全部接受后重试 |
| Android Gradle 下载慢/超时 | 首次需要下载 Gradle 与依赖 | 换网络或配置镜像后重试 |
| 提示 `src-tauri/gen/android` 不存在 | 未初始化 Android 工程 | 先跑 `pnpm tauri android init --ci` |
| 想验证真实上传/下载链路 | 需要云盘凭据 | 跑 `source scripts/env.sh && cargo test --lib -- --ignored live_`，或用 App 的 `--selftest` |

## 发布检查清单

1. **版本号三处同步**：`package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`（打包产物名取 `tauri.conf.json` 的 `version`）。
2. `pnpm check`、`pnpm build` 通过；需要时跑一次 `pnpm tauri dev` 冒烟。
3. 用真实账号跑一次 `--selftest`（或 `cargo test --lib -- --ignored live_`），确认上传→下载字节一致。
4. 更新文档中涉及版本/路径的说明（如产物文件名）。
5. 三端构建（本地脚本或 CI）；Windows / Android 建议至少在 CI 或真机跑通一次。
6. macOS 未签名版自带 `xattr -cr` 提示写进发布说明；Windows 注明 SmartScreen 提示。
7. 如需签名：证书/公证/keystore 走 secrets，不提交仓库。
8. 上传产物到发布页（dmg / setup.exe / apk），附版本与已知限制。
